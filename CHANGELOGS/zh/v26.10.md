## [26.10] - 2026-10-12

面向 **RAPIDS 26.10** + **CUDA 13**(`cu13` wheels)的刷新。仓库内置的 API 索引
基于 **NVIDIA GH200** 上真实的 cuDF / cuML `26.10.00` 安装重新生成。skill 仍覆盖
`cupy`、`cupyx`、`cudf`、`cuml` 四个包。CuPy 保持 `14.2.0`,因此 `cupy.txt` 与
`cupyx.txt` 沿用 26.08 的内容。

### 变更

- **基于 RAPIDS `26.10.00` 重新生成 `apis/cudf.txt` 与 `apis/cuml.txt`**。
  `cudf` 从 4779 条变为 4781 条,`cuml` 从 3290 条变为 3118 条(移除 255 个
  qualname,新增 83 个,改动 645 个)。再加上 `cupy` 的 1067 条与 `cupyx` 的
  1453 条,索引合计 **10419** 条。
- **`cuml.accel` 覆盖范围。** cuML 26.10 新增代理 `sklearn.cluster.HDBSCAN`、
  `sklearn.ensemble.IsolationForest` 与 `sklearn.preprocessing.OneHotEncoder`。
  SKILL.md 的代理清单以及 `sklearn.cluster`、`sklearn.ensemble`、
  `sklearn.preprocessing` 三行映射已写明它们,SKILL.md 中两处打印
  `sklearn.cluster` 行的示例也与新文本一致。
- **SKILL.md 的 dtype 指引。** cuML 26.10 移除了 `convert_dtype` 关键字,skill
  改为要求高精度比对时显式构造 `float64` 输入。它还注明 `NearestNeighbors`
  的距离保持 `float32`,需要 `float64` 距离时改用 `cuml.metrics.pairwise_distances`。
  Example 4 打印新的 `fit` / `kneighbors` 签名。
- **森林推理。** SKILL.md 写明 cuML 26.10 移除了 `cuml.fil` 与
  `cuml.ForestInference`,其后继 `nvforest` 不在 skill 的范围内。
- **`cuml.tsa` 弃用。** `statsmodels.tsa` 映射行与 SKILL.md 目录结构都标注
  `cuml.tsa` 自 26.08 起弃用,计划在 26.12 移除。
- **`sklearn.feature_extraction` 映射行**列出三个 cuML vectorizer
  已经删去的 sklearn 构造参数。
- **SKILL.md 中 cuDF / pandas 条目**改标为 26.10。26.10 接受 pandas
  `>=3.0.0,<3.1.0`(26.08 要求 pandas 低于 3.0.4)。该条目还注明 cuDF 的
  `rename(index=...)` / `reindex` 会跳过 `allows_duplicate_labels=False` 检查。
- **Quick demo 数字**在 1× NVIDIA GH200 120GB 上重新测量(pandas `3.0.6`
  `0.60 秒` → cudf `26.10.00` `0.021 秒`,约 29×)。
- **README / README-zh。** 环境表更新为 Python 3.12.15、cudf 26.10.00、cuml
  26.10.00。pip 安装命令锁定 `26.10.*` 并去掉 `--extra-index-url`,因为 26.10 的
  全部 wheel 及其依赖都已发布到 PyPI。旧安装指南地址 `docs.rapids.ai/install/`
  现已重定向到 `docs.nvidia.com/datascience/install/`,README 链接随之改用新地址。
  环境表下方新增一行,链接到各版本更新日志;它们已从 `CHANGELOG.md` /
  `CHANGELOG-zh.md` 移到 `CHANGELOGS/en/` / `CHANGELOGS/zh/`。
- **`fetch_rapids_apis.py`** 的注释改为写明真实的输出路径 `apis/<pkg>.txt` 与
  映射文件的全名。脚本本身的行为保持不变。

### 修复

以下问题早于 26.10 就已存在,在本次版本审计中发现。

- `cupyx.scipy.spatial.distance` 与 `cupyx.scipy.sparse.csgraph.connected_components`
  在这套技术栈里会抛 `RuntimeError`,因为栈中既没有 cuVS 的 Python 包,也没有
  `pylibcugraph`。`scipy.spatial.distance` 行现指向
  `cuml.metrics.pairwise_distances`,`scipy.spatial` 与 `scipy.sparse.csgraph`
  两行补上了说明,SKILL.md 也把这两个模块列入技术栈的边界。
- `cuml.pipeline.Pipeline` / `make_pipeline` 以 sklearn 原类再导出的形式存在,
  SKILL.md 现改为用它们串联 cuML estimator。
- SKILL.md 中关于签名差异的提醒改用 `init` 举例,
  因为 sklearn 与 cuML 的 `n_init` 默认值都是 `'auto'`。

### 移除

以下 26.10 上游移除项已从重新生成的索引中消失。旧的 `output_type` 取值从未出现在
索引中,现在会在运行时直接报错。skill 文案只依赖上文已处理的条目。

- `cuml.fil`、`cuml.ForestInference` 与 `RandomForestClassifier/Regressor.as_fil`。
- `cuml.experimental` 及其中的 `linear_model.Lars` 别名。`cuml.Lars` 仍然保留。
- `cuml.preprocessing.text` 及其中的 `PorterStemmer`,cuML 中没有替代品。
- 所有 estimator 方法与 metric 上的 `convert_dtype` 关键字。`apis/cuml.txt` 中
  含该关键字的行从 539 降到 0,继续传入会抛 `TypeError`。
- 旧的 `output_type` 取值 `'numba'`、`'array'`、`'dataframe'`、`'series'` 与
  `'df_obj'`,现在会抛 `ValueError`。
- `cuml.metrics.sparse_pairwise_distances`。`pairwise_distances` 直接接受稀疏输入。
- `IsolationForest(warm_start=...)`,以及 `IsolationForest.fit` / `fit_predict`
  的 `sample_weight` 参数。
- `cuml.feature_extraction.text` 各 vectorizer 的 `input`、`encoding`、
  `decode_error`、`strip_accents`、`token_pattern` 参数,构造函数改为只接受关键字
  参数。`delimiter` 默认值改为 `None`,任何非字母数字字符都会切分 token(需要旧
  行为时传 `delimiter=' '`)。`fit` 与 `transform` 的首个参数由 `raw_documents`
  改名为 `X`,`build_preprocessor`、`get_ngrams`、`get_char_ngrams` 已移除。
- 内部模块 `cuml.preprocessing.onehotencoder_mg` / `ordinalencoder_mg`,以及 9 个
  `cuml.testing.utils` 辅助函数。
- cuDF 一侧移除了内部的 `cudf.testing.narwhals_test_plugin`。

### 新增

- **重新生成的索引捕获到的 26.10 新 API 表面**:
  - 29 个公开 cuML estimator 新增 `get_feature_names_out`,内部的 `KMeansMG` /
    `PCAMG` / `TSVDMG` 也有。`get_feature_names` 已弃用,计划在 26.12 移除。
  - `cuml.preprocessing.OneHotEncoder.as_sklearn` / `from_sklearn`。
  - `OneVsRestClassifier.fit` 与 `OneVsOneClassifier.fit` 支持 `sample_weight`。
  - `cudf.DatetimeIndex.indexer_between_time`,返回 `cupy.ndarray`。
  - cuDF Parquet writer 支持 `compression='GZIP'`。其类型注解去掉了 `'ZLIB'`,
    传入 `'ZLIB'` 会在写入时报错。
- **`sklearn.impute` 映射行**,把 sklearn 的 `SimpleImputer` 与
  `MissingIndicator` 指向 `cuml.preprocessing`。

### 说明

- RAPIDS 26.10 于 2026-10-08 在上游发布,支持 Python 3.11 至 3.14、CUDA 12.2 至
  12.9 以及 CUDA 13.0 至 13.3。RAPIDS 26.12 将停止支持 Python 3.11。
- `cuml.accel` 26.10 的测试范围为 scikit-learn 1.6.0 至 1.9.1。
- `cudf.pandas` 与 `cuml.accel` 的零代码激活语法相对 26.08 **保持不变**。
- `nvforest 26.10.00` 与 `pylibraft 26.10.00` 仍作为 cuML 的依赖安装在环境中,
  并 **不在 skill 的范围内**。
