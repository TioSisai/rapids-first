## [26.10] - 2026-10-12

Refresh for **RAPIDS 26.10** on **CUDA 13** (`cu13` wheels). The shipped API index
is regenerated against a live cuDF / cuML `26.10.00` install on an **NVIDIA GH200**.
The skill still covers `cupy`, `cupyx`, `cudf` and `cuml`. CuPy stays at `14.2.0`,
so `cupy.txt` and `cupyx.txt` keep their 26.08 content.

### Changed

- **Regenerated `apis/cudf.txt` and `apis/cuml.txt`** against RAPIDS `26.10.00`.
  `cudf` goes from 4779 to 4781 entries and `cuml` from 3290 to 3118 (255
  qualnames removed, 83 added, 645 changed). With `cupy` 1067 and `cupyx` 1453
  the index holds **10419** entries.
- **`cuml.accel` coverage.** cuML 26.10 newly proxies `sklearn.cluster.HDBSCAN`,
  `sklearn.ensemble.IsolationForest` and `sklearn.preprocessing.OneHotEncoder`.
  The SKILL.md proxy list and the `sklearn.cluster`, `sklearn.ensemble` and
  `sklearn.preprocessing` mapping rows name them, and the two SKILL.md examples
  that print the `sklearn.cluster` row match the new text.
- **Dtype guidance in SKILL.md.** cuML 26.10 removed the `convert_dtype` keyword,
  so the skill asks for explicit `float64` inputs in high-precision comparisons.
  It also notes that `NearestNeighbors` keeps `float32` distances and points to
  `cuml.metrics.pairwise_distances` for `float64` ones. Example 4 prints the new
  `fit` / `kneighbors` signatures.
- **Forest inference.** SKILL.md records that cuML 26.10 removed `cuml.fil` and
  `cuml.ForestInference`, and that their successor `nvforest` stays outside the
  skill.
- **`cuml.tsa` deprecation.** The `statsmodels.tsa` mapping row and the SKILL.md
  directory tree flag `cuml.tsa`, deprecated in 26.08 and set for removal in 26.12.
- **`sklearn.feature_extraction` mapping row** lists the sklearn parameters that
  the three cuML vectorizers dropped.
- **cuDF / pandas bullet** in SKILL.md relabelled for 26.10, which accepts pandas
  `>=3.0.0,<3.1.0` (26.08 capped it below 3.0.4). The bullet also notes that cuDF
  `rename(index=...)` / `reindex` skip the `allows_duplicate_labels=False` check.
- **Quick-demo numbers re-measured** on 1× NVIDIA GH200 120GB (pandas `3.0.6`
  `0.60 s` → cudf `26.10.00` `0.021 s`, ~29×).
- **README / README-zh.** The environment tables list Python 3.12.15, cudf
  26.10.00 and cuml 26.10.00. The pip line pins `26.10.*` and drops
  `--extra-index-url`, because every 26.10 wheel and its dependencies are on PyPI.
  The install-guide link now points to `docs.nvidia.com/datascience/install/`,
  where the old `docs.rapids.ai/install/` address redirects. A line under the
  environment table links the per-version changelogs, which move from
  `CHANGELOG.md` / `CHANGELOG-zh.md` to `CHANGELOGS/en/` / `CHANGELOGS/zh/`.
- **`fetch_rapids_apis.py`** comments name the real output path `apis/<pkg>.txt`
  and the full mapping file name. The script behaves as before.

### Fixed

These errors predate 26.10 and surfaced while auditing this release.

- `cupyx.scipy.spatial.distance` and `cupyx.scipy.sparse.csgraph.connected_components`
  raise `RuntimeError` in this stack, which ships neither the cuVS Python package
  nor `pylibcugraph`. The `scipy.spatial.distance` row now targets
  `cuml.metrics.pairwise_distances`, the `scipy.spatial` and `scipy.sparse.csgraph`
  rows carry the caveat, and SKILL.md lists both modules among the stack's edges.
- `cuml.pipeline.Pipeline` / `make_pipeline` exist as re-exports of sklearn's
  classes, and SKILL.md now names them for chaining cuML estimators.
- The signature reminder in SKILL.md cites `init` in place of `n_init`, since both
  libraries default to `n_init='auto'`.

### Removed

These upstream 26.10 removals are gone from the regenerated index. The legacy
`output_type` values never appeared in it and fail at runtime instead. Skill text
relied only on the items covered above.

- `cuml.fil`, `cuml.ForestInference` and `RandomForestClassifier/Regressor.as_fil`.
- `cuml.experimental` and its `linear_model.Lars` alias. `cuml.Lars` remains.
- `cuml.preprocessing.text` and its `PorterStemmer`, with no cuML replacement.
- The `convert_dtype` keyword on every estimator method and metric, where passing
  it raises `TypeError`. Lines of `apis/cuml.txt` that mention it drop from 539 to 0.
- The legacy `output_type` values `'numba'`, `'array'`, `'dataframe'`, `'series'`
  and `'df_obj'`, which now raise `ValueError`.
- `cuml.metrics.sparse_pairwise_distances`. `pairwise_distances` takes sparse input.
- `IsolationForest(warm_start=...)` and the `sample_weight` argument of
  `IsolationForest.fit` / `fit_predict`.
- The `input`, `encoding`, `decode_error`, `strip_accents` and `token_pattern`
  parameters of the `cuml.feature_extraction.text` vectorizers, whose constructors
  are now keyword-only. `delimiter` defaults to `None`, so any non-alphanumeric
  character splits tokens (pass `delimiter=' '` for the old behaviour). `fit` and
  `transform` take `X` in place of `raw_documents`, and `build_preprocessor`,
  `get_ngrams` and `get_char_ngrams` are gone.
- The internal `cuml.preprocessing.onehotencoder_mg` / `ordinalencoder_mg` modules
  and 9 `cuml.testing.utils` helpers.
- On the cuDF side, the internal `cudf.testing.narwhals_test_plugin`.

### Added

- **New 26.10 API surface** captured by the regenerated index:
  - `get_feature_names_out` on 29 public cuML estimators and the internal
    `KMeansMG` / `PCAMG` / `TSVDMG`. The older `get_feature_names` is deprecated
    and set for removal in 26.12.
  - `cuml.preprocessing.OneHotEncoder.as_sklearn` / `from_sklearn`.
  - `sample_weight` on `OneVsRestClassifier.fit` and `OneVsOneClassifier.fit`.
  - `cudf.DatetimeIndex.indexer_between_time`, which returns a `cupy.ndarray`.
  - `compression='GZIP'` for the cuDF Parquet writer. Its annotation drops
    `'ZLIB'`, which raises at write time.
- **`sklearn.impute` mapping row**, which points `SimpleImputer` and
  `MissingIndicator` at `cuml.preprocessing`.

### Notes

- RAPIDS 26.10 shipped upstream on 2026-10-08. It supports Python 3.11 to 3.14,
  CUDA 12.2 to 12.9 and CUDA 13.0 to 13.3. RAPIDS 26.12 drops Python 3.11.
- `cuml.accel` 26.10 is tested against scikit-learn 1.6.0 to 1.9.1.
- Zero-code activation syntax for `cudf.pandas` and `cuml.accel` is
  **unchanged** from 26.08.
- `nvforest 26.10.00` and `pylibraft 26.10.00` remain installed as dependencies of
  cuML and stay **out of scope** for the skill.
